# Архитектура репозитория

Этот репозиторий хранит персональную конфигурацию NixOS, пользовательскую конфигурацию Home Manager и окружения разработки Nix. Единой точкой входа является `flake.nix`.

## Поток конфигурации

```text
flake.nix
|- nixosConfigurations.pepegov -> nixos/configuration.nix -> nixos/modules/
|- homeConfigurations.pepegov  -> home-manager/home.nix   -> home-manager/modules/
`- devShells.x86_64-linux      -> shells/default.nix      -> shells/*.nix
```

`flake.nix` фиксирует внешние зависимости во `flake.lock`, задает платформу `x86_64-linux`, импортирует стабильный `nixpkgs` и `nixpkgs-unstable`, а также экспортирует три типа результатов:

- `nixosConfigurations.pepegov` - системная конфигурация NixOS;
- `homeConfigurations.pepegov` - пользовательская конфигурация Home Manager;
- `devShells.x86_64-linux` - именованные среды разработки.

В NixOS передаются `inputs` и `pkgs-unstable` через `specialArgs`; в Home Manager - через `extraSpecialArgs`. Благодаря этому модули могут использовать входы флейка и пакеты из нестабильного канала, если объявят соответствующие аргументы.

## NixOS

`nixos/configuration.nix` - главный системный модуль. Он импортирует `hardware-configuration.nix` и конкретные файлы из `nixos/modules/`. В нем также находятся базовые настройки системы: локаль, часовой пояс, системные пакеты, Firefox, Nix features и `system.stateVersion`.

`nixos/modules/` содержит независимые системные модули. Обычно каждый файл отвечает за одну область: загрузку, оборудование, звук, сессию, пользователей, виртуализацию, печать, монтирование, GPG, рабочие сервисы или сборщик мусора. Модуль возвращает Nix attribute set с настройками NixOS и при необходимости принимает аргументы, например `{ config, pkgs, lib, pkgs-unstable, inputs, ... }`.

Для сети используется отдельный агрегирующий модуль `nixos/modules/networking/networking.nix`. Он сам импортирует подмодули из `nixos/modules/networking/`, поэтому новый связанный с сетью модуль нужно добавить в его `imports`, а не только создать файл.

Чтобы добавить системный модуль:

1. Создай `nixos/modules/<имя>.nix` с NixOS-опциями.
2. При необходимости положи связанные файлы рядом с модулем и обращайся к ним относительным путем.
3. Добавь модуль в `imports` файла `nixos/configuration.nix` или в `nixos/modules/networking/networking.nix` для сетевой функциональности.

Некоторые модули ссылаются на локальные данные вне отслеживаемой конфигурации. Их содержимое не является частью архитектуры, описываемой здесь.

## Home Manager

`home-manager/home.nix` - главный пользовательский модуль. Он задает учетную запись, домашний каталог, версию состояния, несколько базовых пакетов и Bash-алиасы. Главное назначение файла - импортировать все модули из `home-manager/modules/`.

Каждый каталог в `home-manager/modules/` представляет отдельную функцию пользовательского окружения. Его обязательная точка входа - `default.nix`. Такие модули могут:

- устанавливать пользовательские пакеты через `home.packages`;
- создавать конфигурационные файлы через `home.file` или `xdg.configFile`;
- устанавливать пользовательские службы и таймеры systemd;
- создавать скрипты и desktop-файлы с помощью функций `pkgs`;
- хранить дополнительные файлы в каталогах `config/` и `assets/` рядом с `default.nix`.

Дополнительные файлы модуля подключаются из его `default.nix` относительными путями. Конфигурации часто развертываются в домашний каталог как файлы, каталоги или исполняемые скрипты. Например, модуль может использовать `source` для готового файла или `text` для небольшого генерируемого файла.

Чтобы добавить модуль Home Manager:

1. Создай каталог `home-manager/modules/<имя>/` и файл `default.nix`.
2. Помести относящиеся к нему конфиги, скрипты и ассеты внутри этого каталога, обычно в `config/` или `assets/`.
3. Добавь путь `./modules/<имя>` в список `imports` файла `home-manager/home.nix`.
4. Не помещай локальные секреты и приватные данные в модуль или его дополнительные файлы.

Модуль `home-manager/modules/agents/` разворачивает конфигурации агентов, их профили и навыки в пользовательский каталог. Он также содержит специальные activation steps для файлов, которые должны быть обычными файлами, а не символьными ссылками.

## Flake и применение конфигураций

Флейк связывает системную и пользовательскую части, но это самостоятельные outputs. Системная конфигурация применяется как NixOS-конфигурация хоста `pepegov`; Home Manager применяется как конфигурация пользователя `pepegov`. Команда `nixos-rebuild` с флейком использует output `nixosConfigurations.pepegov`; команды Home Manager используют `homeConfigurations.pepegov`.

После добавления новых входов в `flake.nix` их версии фиксируются в `flake.lock`. Не меняй `flake.lock` вручную: его обновляет Nix при обновлении входов.

## Development shells

`shells/default.nix` экспортирует attribute set именованных development shells. `flake.nix` публикует этот set как `devShells.x86_64-linux`.

Сейчас shell `dotnet` определен в `shells/dotnet.nix`. Он создает `mkShell` с SDK и runtime .NET, инструментами Node.js, Bun и Git, нативными библиотеками и `shellHook`, который готовит переменные окружения. Запуск выглядит так:

```bash
nix develop .#dotnet
```

Модуль Home Manager `home-manager/modules/nix-shell/` использует тот же shell для desktop-запуска Rider: он выполняет `nix develop <путь-к-репозиторию>#dotnet` и очищает конфликтующие переменные окружения перед запуском IDE.

Чтобы добавить новый shell:

1. Создай `shells/<имя>.nix`. Файл должен принимать нужные аргументы, например `{ pkgs, pkgs-unstable, ... }`, и возвращать `pkgs.mkShell`.
2. Определи `nativeBuildInputs`, `buildInputs` и при необходимости `shellHook`.
3. Добавь `<имя> = import ./<имя>.nix { inherit pkgs pkgs-unstable; };` в attribute set `shells/default.nix`.
4. Запускай его командой `nix develop .#<имя>` из корня репозитория.

Если shell требует локальных данных, запроси их у пользователя и не читай папку `hidden`.
